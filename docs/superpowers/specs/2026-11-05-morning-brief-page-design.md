# 아침 뉴스 브리핑 페이지 설계

작성일: 2026-11-05 · 상태: 승인됨, 구현 완료(2026-11-06)

## 의도

매일 아침 휴대폰 브라우저로 열어, 국내외 언론사의 관심 뉴스를 약 4분 안에 파악하는 개인용 페이지다.

기존 `daily-youtube-news`는 뉴스 영상을 플레이리스트로 모아 주지만 듣는 시간이 길다. 시험 중인 음성 브리핑도 7~8분이다. 이 페이지는 같은 관심 분야를 글로 읽고 끝내는 것이 목적이다. 원문을 보여 주지 않고, AI가 요약하고 쉽게 풀어 쓴다.

## 목표

- 사용자 한 명이 매일 아침 페이지를 열면 그날 브리핑이 바로 보인다.
- 국내외 언론사 기사를 모아 같은 사건은 하나로 합친다.
- 맨 앞에 미국 시황 카드 최대 6장을 보여 주고, 이어서 중요한 뉴스를 합쳐 총 12장을 제목과 본문 블록 1~3개로 보여 준다. 첫 블록만 읽으면 약 4분에 끝나고, 더 알고 싶은 기사만 다음 블록을 본다.
- 해외 기사도 한국어로 풀어서 보여 준다.
- 나머지 관심 뉴스는 마무리 화면에 제목만 보여 준다.

## 하지 않는 것

- 로그인, 사용자별 관심사, 다른 사람을 위한 서비스
- 기사 본문 수집이나 전문 표시
- 뉴스 검색, 댓글, 알림, 앱 설치
- 기존 YouTube 플레이리스트 변경. 플레이리스트는 그대로 유지한다.

## 실패로 보는 경우

- 읽는 데 음성 브리핑만큼 시간이 걸린다.
- 근거에 없는 사실이나 숫자가 요약에 들어간다.
- 아침에 열었을 때 비어 있거나 오류 화면이 나온다.
- 이 작업 때문에 운영 중인 플레이리스트 생성이 망가진다.

## 제약

- 저장소 `xxxbeom-glitch/daily-youtube-news`는 공개 저장소다. 브리핑 결과를 커밋하지 않는다. 비밀값은 GitHub Secrets와 Vercel 환경 변수에만 둔다.
- 기존 Vercel 함수 제한은 60초다. 수집과 AI 처리는 Vercel 함수에서 하지 않는다.
- GitHub Actions의 `schedule`은 지연이나 누락 사례가 있고, 공개 저장소는 60일간 활동이 없으면 예약이 꺼진다. 그래서 예약을 두 번 걸어 뒤의 실행이 앞 실행을 보완한다.
- 뉴욕증시는 겨울에 06:00 KST, 여름에 05:00 KST에 마감한다. 사용자는 08:00 KST쯤 읽으므로 생성은 07:00 KST대에 시작해 마감 기사가 들어갈 시간을 둔다.
- 피드의 설명은 평균 70~300자이고 한국경제처럼 설명이 없는 피드도 있다. 구글 뉴스 검색 결과의 설명은 제목과 언론사 이름뿐이다(2026-11-06 확인). 본문은 제목과 설명만 근거로 쓴다.

## 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| Actions + 저장소에 커밋 | 결과 파일을 저장소에 저장 | 요약이 공개 저장소에 쌓이고 매일 재배포가 일어나 제외 |
| **Actions + Vercel Blob** | Actions가 만들고 결과만 Blob에 저장 | **사용자 선택.** 시간 제한이 여유롭고 배포 없이 내용이 바뀐다 |
| Vercel Cron에서 모두 처리 | 함수 하나로 수집부터 저장까지 | 시간 초과로 브리핑이 비는 위험이 있어 제외 |

실행 환경은 GitHub Actions와 Claude Code 클라우드 예약 작업을 비교했고, 사용자가 Actions를 골랐다. 클라우드 예약 작업은 구독 한도에 걸리면 실행이 거부되고, 연구 미리보기 단계다.

## 사용자가 정한 것

- 혼자 쓰는 개인용이다.
- 관심 분야는 2026-11-06 설문으로 정했다. 목록은 `### 2. 수집 주제`에 있다.
- 뉴스 하나는 제목과 2~3줄 핵심 내용으로 보여 주고, 내용이 충분한 기사는 본문을 2~3블록으로 나눈다.
- 옆으로 밀면 다음 기사, 위로 밀면 같은 기사의 다음 블록이다.
- 화면은 B타입(한 장씩 넘기기)이고 손으로 밀어서만 넘긴다.
- 카드 12장과 나머지 제목 목록으로 구성한다.
- 첫 카드부터 미국 시황을 최대 6장 보여 준다. 지수, 정치·국제정세, 기업 순서이고 기업 카드는 이슈가 크면 최대 4장까지 쓴다. 시황은 중요하므로 한 장으로 압축하지 않는다.
- 수집 주제는 사용자가 2026-11-06 설문에서 고른 항목을 기준으로 한다. 목록은 `### 2. 수집 주제`에 있다.
- 해외 사건 카드는 시황을 뺀 일반 뉴스 중 최대 5장이다. 미국 내부 뉴스는 세계 경제나 한국에 영향이 있을 때만 넣는다.
- 브리핑은 08:00 KST쯤 읽는다.
- GitHub Actions와 Vercel Blob을 쓴다.

## 전체 구조

```text
GitHub schedule (07:10 KST, 재시도 07:40 KST)
    → GitHub Actions: 수집 → 시황 카드 작성 + 일반 뉴스 고르기 → 카드 작성 → 검증
      → /api/ingest (GitHub OIDC 서명 확인)
        → Vercel Blob: briefings/YYYY-MM-DD.json, briefings/latest.json
          ← 모바일 페이지가 /api/briefing을 거쳐 읽음
```

코드는 같은 저장소의 새 폴더 `morning-brief/`에 둔다. 페이지는 기존과 별도인 Vercel 프로젝트 `morning-news-mockup`으로 배포한다. 기존 프로젝트의 `vercel.json`, `api/`, cron은 바꾸지 않는다.

## 브리핑 생성

### 1. 수집

- 언론사 목록은 `morning-brief/sources.json`에 둔다. 각 항목은 이름, 주소, 국내외 구분, 언어를 가진다.
- 시작 목록은 연합뉴스, 한겨레, 경향신문, SBS, JTBC, 매일경제, 한국경제, 구글 뉴스 한국판, BBC, 가디언, 뉴욕타임스, 알자지라, CNBC, NPR, 구글 뉴스 경유 로이터다. 2026-11-05에 모두 응답을 확인했다.
- 수집 구간은 전날 18:00 KST부터 실행 시각까지다.
- 시황 전용 수집원은 `sources.json`에 `market` 용도로 표시한다. 시작 목록은 구글 뉴스 `뉴욕증시 마감` 검색, 구글 뉴스 `wall street stocks close` 검색, CNBC 시장·경제 피드, 연합뉴스 마켓 피드다. 2026-11-05에 모두 응답을 확인했다. CNBC 기술 피드(`id/19854910`)와 주제별 구글 뉴스 검색을 더한다. MarketWatch 피드는 2025년 기사에서 멈춰 있어 뺐다.
- 피드 하나가 실패해도 전체를 멈추지 않는다. 실패한 피드는 실행 로그와 결과 파일의 `sourceErrors`에 남긴다.
- 시황 전용을 뺀 정상 피드가 5개 미만이면 생성을 실패로 처리한다.
- 날짜가 없는 항목은 이전 실행과 비교할 수 없으므로 수집 시각을 날짜로 쓴다.
- 기사 주소가 같으면 하나만 남긴다.

### 2. 수집 주제

주제 목록은 `morning-brief/topics.json`에 둔다. 각 항목은 주제 이름, 들어갈 카드, 검색어, 언어를 가진다. 코드를 고치지 않고 주제를 바꿀 수 있어야 한다.

- 영어 주제는 구글 뉴스 검색에 로이터, 블룸버그, WSJ, CNBC, FT의 `site:` 조건을 붙인다. 조건이 없으면 주요 언론 기사가 주제별로 0~3건만 잡히고 전망 사이트와 광고성 글이 섞인다. 조건을 붙이면 주제마다 83~100건이 잡혔다(2026-11-06 확인).
- 한국어 주제는 구글 뉴스 한국판 검색과 기존 국내 피드를 쓴다.
- 주제별 입력은 최신 20건까지로 제한해 AI 비용을 묶어 둔다.

| 카드 | 주제 |
|---|---|
| `미국 시황` | 미국 지수 마감 |
| `시장과 정치` | 트럼프, 이란 전쟁과 호르무즈, 러시아·우크라이나 전쟁 |
| `환율·원자재` | 원달러 환율, 달러, 유가·에너지, 금·원자재 |
| `반도체` | 반도체 업황, 메모리값, 엔비디아, TSMC, AMD, 퀄컴, 브로드컴, 삼성전자, SK하이닉스, 젠슨 황 |
| `빅테크` | 마이크로소프트, 애플, 구글, 아마존, 메타, 테슬라, 머스크, 저커버그 |
| `AI 기업` | 오픈AI, 앤트로픽, xAI, 딥시크 등 중국 AI, 새 AI 모델 출시, 데이터센터·전력, 샘 올트먼, 다리오 아모데이 |
| 기업 카드 공통 | 기업 실적 발표, IPO |
| 일반 뉴스 | 외교·안보, 북한, 감염병, IT 기기 |

- 설문에서 고르지 않은 금리·연준, 경제지표, 가상자산, 인수합병, 국내 정치, 사건·사고, 건강, 교육, 연예, 스포츠는 전용 검색을 두지 않는다. 금리 같은 주제는 지수가 움직인 이유로 기사에 나오면 쓸 수 있다.
- 코스피는 평소에 다루지 않는다. 사용자가 일상 주제로는 고르지 않고 급락 이슈만 골랐기 때문이다. 급락이나 급등을 다룬 제목이 5곳 이상의 언론사에서 나온 날만 일반 카드로 만든다. 이 기준은 설계 단계에서 정한 값이다.

### 3. 미국 시황 카드

일반 뉴스와 따로 AI 호출 1회로 처리한다. 시황은 중요도 경쟁에 넣지 않고 항상 맨 앞에 둔다.

- 입력은 시황 전용 수집원의 기사와 일반 피드에서 뉴욕증시·미국 금리·달러·유가를 다룬 기사다. 프로그램이 키워드로 먼저 추린다.
- 카드는 아래 순서로 최대 6장 만든다. 근거가 없는 카드를 채우려고 내용을 만들지 않는다.

| 순서 | 분야 | 내용 | 조건 |
|---|---|---|---|
| 1 | `미국 시황` | 주요 지수 마감과 이유를 짧게 | 증시가 열린 날 항상. 마감 결과라고 명시된 기사만 쓴다 |
| 2 | `시장과 정치` | 트럼프 발언, 전쟁, 국제정세와 시장의 연관성 | 기사 자체가 시장과 연결해 말한 경우만 |
| 3 | `환율·원자재` | 환율, 달러, 유가, 금의 움직임 | 주요 언론 헤드라인이 있을 때만 |
| 4 | `반도체`, `빅테크`, `AI 기업` | 기업과 오너의 사건 | 주요 언론 헤드라인만. 종목 추천 글은 뺀다. 비상장 AI 기업은 투자, IPO, 새 모델, 소송 같은 실제 사건이 있을 때만 쓰고 회사가 직접 쓴 글은 뺀다 |

- 기업 카드(`반도체`, `빅테크`, `AI 기업`)는 합쳐서 기본 1~2장, 최대 4장이다. 시황 구역 전체는 최대 6장이고, 넘치면 근거 언론사가 적은 기업 카드부터 뺀다. 카드 하나는 기업 사건 하나만 다룬다. 3장째부터는 정해 둔 언론사 3곳 이상이 헤드라인으로 다룬 사건만 넣는다.

- 근거는 제목과 설명뿐이다. 카드 하나를 만들려면 설명이 있는 기사 1건 이상, 또는 같은 사건을 다룬 서로 다른 언론사 제목 3건 이상이 있어야 한다. 근거가 부족하면 카드를 빼거나 1블록으로 끝낸다.
- 기사에 없는 원인이나 연관성은 AI가 추론해 쓰지 않는다.
- 카드 규칙은 일반 카드와 같다. 블록 하나는 140자 이하, 링크는 최대 5개다.
- 미국 증시가 쉰 날은 마감 기사가 없다. 일요일, 월요일 아침과 미국 휴장일 다음 날이 해당한다. 이때는 지수, 정치, 환율·원자재 카드를 빼고 기업 카드는 뉴스가 있으면 유지한다. 남은 자리는 일반 뉴스로 채워 12장을 만든다.
- 시황 단계가 실패해도 브리핑 생성은 계속하고, 일반 뉴스로 12장을 채운다.
- 시황 카드에 쓴 기사는 일반 뉴스 고르기에서 뺀다. 같은 내용이 뒤에 다시 나오지 않게 하기 위해서다.

### 4. 고르기와 묶기

AI 호출 1회로 처리한다.

- 입력은 기사 번호, 언론사, 제목, 설명 앞 300자다. 영어 기사는 번역하지 않고 그대로 넣는다.
- 출력은 사건 묶음이다. 각 묶음은 기사 번호 목록, 분야, 중요도 0~100, 국내·해외 구분을 가진다.
- 국내·해외 구분은 언론사가 아니라 사건 기준이다. 해외 언론이 보도해도 한국 관련 사건이면 국내로 본다.
- 미국 내부 뉴스는 세계 경제나 한국에 영향이 있을 때만 후보에 넣는다.
- 일반 카드는 `일반 뉴스` 주제와 시황 카드에 쓰지 않은 전쟁 소식을 먼저 고른다. 6장을 못 채우는 날만 관심 밖의 큰 뉴스로 채운다. 큰 뉴스는 중요도가 높고 여러 언론사가 다룬 사건이다.
- 포함과 제외 기준은 `lib/select.js`의 현재 기준을 따른다. 단순 정당 공방, 연예 가십, 스포츠, 사소한 지역 단신은 제외한다.
- 기사 내용은 신뢰할 수 없는 입력으로 다루고, 그 안의 지시문은 따르지 않는다.
- 프로그램이 해외 묶음을 최대 5장으로 제한한다. 이 제한은 시황을 뺀 일반 카드에 적용한다.
- 일반 카드 순서는 시황 뒤에서 관심 주제를 먼저, 그 안에서 중요도순으로 하고, 같은 분야가 3건 이상 연속되지 않게 한다. `orderByImportanceWithDiversity`와 같은 규칙이다.

### 5. 카드 작성

AI 호출 1회로 처리한다.

- 근거가 제목뿐인 묶음은 카드 후보에서 빼고 제목 목록으로 보낸다.
- 상위 15개 묶음의 카드를 만든다. 시황 장수를 뺀 나머지를 채우고 남는 카드는 검증에서 빠질 때를 대비한 예비다. 각 카드는 분야, 제목, 본문 블록 1~3개, 기사 번호 목록을 가진다.
- 카드가 되지 않은 나머지 묶음은 한국어 제목만 만든다. 최대 30건까지만 표시한다.
- 카드 본문은 그 묶음에 속한 기사 전체의 제목과 설명을 근거로 쓴다.
- 블록을 나누는 목적은 내용을 쪼개는 것이 아니라 더 많이 담는 것이다. 지나친 압축으로 놓치는 내용이 없도록, 근거가 충분하면 본문을 140자 넘게 쓰고 블록으로 정리한다.
- 본문 전체가 140자 이내면 무조건 1블록이다. 둘째 블록부터는 60자 이상이어야 하고, 짧으면 앞 블록에 합친다. 프로그램이 이 규칙을 확인해 합친다.
- 근거에 서로 다른 사실이 충분하지 않으면 1블록으로 끝낸다. 언론사가 하나뿐인 기사는 대부분 1블록이 된다.
- 블록 순서는 무슨 일인가, 왜 중요한가, 앞으로 볼 점이다. 앞 블록의 말을 되풀이하지 않고, 근거가 없는 블록은 만들지 않는다.
- 첫 블록만 읽어도 사건을 이해할 수 있어야 한다.
- 카드에 표시할 링크는 프로그램이 묶음의 기사 중 최대 5개를 고른다. 언론사가 겹치지 않게 하고, 가능하면 국내와 해외 언론사를 섞는다. 5개가 안 되면 있는 만큼만 표시한다.
- 문체는 쉬운 해요체다. 어려운 용어는 본문 안에서 짧게 풀어 쓴다.
- 제목은 화면에서 최대 2줄이다. 공백 포함 18자 안팎으로 쓰고, 프로그램이 20자를 넘는 제목을 확인해 그 카드만 다시 쓰게 한다. 띄어쓰기 없는 7자 이상 단어는 줄바꿈이 어려워 3줄로 넘칠 수 있으므로 제목에서 줄여 쓴다.
- 블록 하나는 140자까지 채워 써도 되고 넘기지 않는다. 내용이 적으면 억지로 늘리지 않는다. 근거가 적으면 더 짧아도 되고 내용을 늘려 쓰지 않는다.
- 입력에 없는 사실, 숫자, 이름, 인용을 만들지 않는다. 용어 풀이는 사건과 무관한 일반 정의일 때만 예외로 허용한다.
- 원문 주소는 AI가 쓰지 않는다. 프로그램이 기사 번호로 연결한다.

### 6. 검증과 저장

- AI 호출 1회로 시황 카드와 일반 카드를 근거 기사와 대조한다. 입력에 없는 사실, 숫자, 원인이나 연관성이 첫 블록에 있으면 그 카드를 빼고, 둘째 블록 이후에 있으면 그 블록만 뺀다. 블록을 뺀 뒤에도 블록 합치기 규칙을 다시 적용한다. 추가 비용은 월 몇십 센트 수준으로 추정한다.
- 문제 있는 카드는 고치지 않고 빼며, 시황 카드가 빠져도 일반 예비 카드로 채워 최대 12장을 만든다. 빠진 묶음은 제목 목록으로 옮기지 않는다.
- 시황을 뺀 일반 카드가 6건 미만이면 실패로 처리한다.
- 카드의 언론사와 원문 주소는 실제 수집 기사와 일치해야 한다.
- 검증을 통과한 뒤에만 `briefings/YYYY-MM-DD.json`을 먼저 쓰고 `briefings/latest.json`을 교체한다.
- 생성에 실패하면 기존 `latest.json`을 유지한다. Actions 실행은 실패로 끝나서 GitHub 알림이 온다.
- 파일은 14일 동안 보관하고 그 이전 파일은 실행할 때 지운다.

## 모델과 비용

- 이 프로젝트가 이미 쓰는 OpenAI Responses API와 `gpt-5.6-luna`를 쓴다. 모델은 환경 변수로 바꿀 수 있게 한다.
- 2026-11-05 측정값은 13개 피드, 14시간 482건, 약 7만 자다. 일부 피드는 개수 제한이 있어 실제는 더 많을 수 있다.
- 추정 사용량은 시황 호출과 본문 블록을 더해 하루 입력 약 10만 토큰, 출력 약 2만 토큰이다.
- 공식 요금은 입력 100만 토큰당 0.20달러, 출력 100만 토큰당 1.20달러다. 추정 비용은 하루 약 0.05달러, 월 약 1.3달러다.
- 입력이 20만 토큰을 넘으면 설명을 줄여서 다시 시도한다. 27만 2천 토큰을 넘는 요청은 요금이 높아진다.

## 실행 예약

- GitHub Actions `schedule`이 22:10 UTC(07:10 KST)와 22:40 UTC(07:40 KST)에 워크플로를 실행한다. 처음 설계한 Vercel Cron 호출은 GitHub 토큰을 저장해야 해서 재시도 예약으로 바꿨다.
- 워크플로는 동시 실행을 막고, 시작할 때 오늘 브리핑이 이미 있으면 생성을 건너뛴다. 앞 실행이 늦거나 실패해도 뒤 실행이 만든다.
- 둘 다 실패하면 어제 브리핑을 날짜 안내와 함께 보여 준다. 생성 실패는 GitHub 알림으로 남는다.
- 드물게 두 예약이 모두 늦으면 08:00을 조금 넘길 수 있다. 이 경우 어제 브리핑이 보이다가 다시 열 때 오늘 브리핑으로 바뀐다.
- 워크플로는 수동 실행도 지원한다. 수동 실행은 `force` 입력을 주면 그날 파일을 새로 만든다.
- 필요한 비밀값은 `OPENAI_API_KEY`(GitHub Secrets), `BLOB_READ_WRITE_TOKEN`, `BRIEF_ACCESS_TOKEN`(Vercel)이다.
- Actions는 Blob 토큰을 갖지 않는다. 결과를 `/api/ingest`로 보내고, 이 함수는 GitHub OIDC 토큰의 서명과 저장소, `main`, 워크플로 경로를 확인한 뒤 Blob에 쓴다. 저장된 공유 비밀값이 없다.
- Actions 로그는 공개이므로 브리핑 내용을 남기지 않고 개수만 남긴다.

## 접근 제한

- Blob 저장소는 비공개로 쓴다. 공개 URL을 만들지 않는다.
- 처음 한 번 전용 주소 `/b/<BRIEF_ACCESS_TOKEN>`로 들어오면 1년짜리 HttpOnly 쿠키를 받고 `/`로 이동한다. 이후에는 그 브라우저에서 기본 주소로 열린다.
- `/api/briefing`이 쿠키를 확인한 뒤 Blob을 읽어 돌려준다. 쿠키가 없으면 401이고 화면은 전용 주소 안내를 보여 준다. 비밀번호 입력 화면은 만들지 않는다.
- 모든 페이지에 `noindex`를 넣는다.

### 흐름

표지 없이 첫 카드부터 바로 시작한다.

1. **카드 12장:** 미국 시황 최대 6장이 먼저 나오고 일반 뉴스가 이어진다. 각 카드는 분야, 제목, 본문 블록 1~3개, 근거 기사 링크 최대 5개. 링크는 언론사 이름으로 표시하고 화면 아래 고정 영역에 줄바꿈 없이 한 줄로 보여 준다. 한 줄에 다 들어가지 않으면 들어가는 만큼만 표시한다. 블록을 넘겨도 이 영역은 움직이지 않는다. 누르면 원문이 새 탭으로 열린다.
2. **마무리:** 오늘 카드 제목 목록과 그 밖의 제목. 카드 제목을 누르면 해당 카드로 돌아가고, 그 밖의 제목을 누르면 원문이 열린다.

### 동작

- 옆으로 밀면 다음 기사로 넘어간다. 이전·다음 버튼은 두지 않는다.
- 블록이 더 있는 기사는 위로 밀면 현재 블록이 사라지고 다음 블록이 나온다. 제목과 출처는 그대로 고정한다.
- 블록이 여러 개면 분야 옆에 작은 점으로 위치를 보여 주고, 첫 블록에 위로 밀어 더 보기 안내를 표시한다.
- 화면 맨 위에 붙은 2px 막대가 읽은 위치를 채워서 보여 준다.
- 카드가 들어올 때 제목이 단어별로 올라오고 첫 블록과 출처가 차례로 나타난다. 다시 돌아와도 재생되며, 움직임 줄이기 설정에서는 바로 표시한다.
- 읽던 위치는 날짜별로 브라우저에 저장한다. 다시 열면 그 카드부터 나온다. 날짜가 바뀌면 첫 카드부터 시작한다.

## 알려진 위험

- 피드 주소와 형식은 예고 없이 바뀔 수 있다.
- 짧은 설명만으로 쓴 요약은 깊이가 얕을 수 있다. 첫 2주 동안 실제 결과를 보고 프롬프트를 조정한다.
- 전용 주소가 유출되면 누구나 볼 수 있다. 환경 변수를 바꾸면 주소와 기존 쿠키가 모두 바뀐다.
- 기사 제목 사용과 요약 표시는 개인 이용을 전제로 한다. 다른 사람에게 공개하려면 저작권 검토가 먼저 필요하다.
